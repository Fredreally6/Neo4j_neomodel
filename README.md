# Concept Similarity in Weighted Knowledge Graphs

Research scripts for measuring similarity between concepts in a weighted knowledge graph, using Neo4j and neomodel. A concept is represented by a node and its outgoing relations: two concepts can be similar because they share features directly, or because their neighboring concepts have similar descriptions.

The project explores the method described in **Similarity of Concepts in Weighted Knowledge Graphs** by Yongfan Wang, Ronald R. Yager, and Marek Z. Reformat (IPMU 2024).

## Approach

The comparison combines three ideas:

- **Direct similarity:** matching relation types and identical tail nodes contribute according to their edge weights, combined with a T-norm.
- **Indirect similarity:** matching relation types with different tail nodes trigger recursive comparisons of those tail nodes.
- **Aggregation across levels:** deeper comparisons contribute through a user-defined coefficient for two levels, or weights generated by InHyp-OWA for more levels.

Two scripts implement different normalization choices. `og_maxAB.py` uses the larger sum of outgoing edge weights of the two compared nodes (symmetric comparison). `og_A2B.py` uses the sum for the second node, making the comparison directional and relative to that node.

These are small experimental scripts with toy graphs, rather than a packaged library. The current T-norm is `min(a, b)`; the paper also studies Product and Lukasiewicz T-norms.

## Files

| File | Purpose |
| --- | --- |
| `data_load.py` | Load a weighted CSV graph into Neo4j; defaults to `data/example3.csv`. |
| `model.py` | Define the `Rootnode` and `Normalnode` node types. |
| `og_maxAB.py` | Compare root nodes `A` and `B` using symmetric normalization. |
| `og_A2B.py` | Compare `A` to `B` using directional normalization. |

## Getting started

### 1. Prepare the environment

Use Python 3 and a running Neo4j instance with Bolt access. Install the Python dependencies:

```bash
python -m pip install pandas neomodel
```

The loader also requires the Neo4j APOC plugin, with `apoc.create.relationship` available. The older Py2neo scripts are not needed for the workflow below.

Set `config.DATABASE_URL` in `data_load.py`, `og_maxAB.py`, and `og_A2B.py` to your connection details. The current default is:

```python
config.DATABASE_URL = "bolt://neo4j:password@localhost:7687"
```

**Use a dedicated experimental database: `data_load.py` deletes all nodes and relationships in the connected database before loading the CSV.**

### 2. Load an example graph

Run all commands from the repository root so the relative data paths resolve:

```bash
python data_load.py
```

The default input is `data/example3.csv`. Each row describes a directed, weighted relation, with columns in this order:

```csv
entity1,relation,entity2,weight
A,R101,X101,0.9
B,R101,X101,0.5
```

The loader creates `A` and `B` as `Rootnode` nodes, other entities as `Normalnode` nodes, and stores each edge's weight in the `weight` property. Use weights in `[0, 1]` for the weighted similarity experiments.

### 3. Calculate similarity

```bash
python og_maxAB.py
python og_A2B.py
```

Each script prints the comparisons at each level, the aggregation weights, and a final similarity score. Both compare `A` and `B` by default. In `og_A2B.py`, the result is normalized relative to `B`; reversing the arguments gives a comparison relative to `A`.

## Trying other settings

- **Input graph:** change the CSV path in `data_load.py` and run the loader again. `example1.csv` contains the root-level features, `example2.csv` adds one deeper level, and `example3.csv` adds a second deeper level. `example1v.csv` adds shared features; `example1as.csv` adds features on the `A` side. Some older CSV files have no weight column and cannot be used directly with the current loader.
- **Depth:** set `layer` in either comparison script. `1` uses level 0 only, `2` includes levels 0 and 1, and the default `3` includes levels 0, 1, and 2.
- **Level weights:** when `layer = 2`, `alpha` controls the deeper level's contribution (default `0.5`). With `layer >= 3`, the scripts generate InHyp-OWA weights using the number of direct matches at the root, falling back to `1` if there are none.
- **T-norm:** edit `tNorm` in `norm.py` to explore a different operator.

Settings and node names are edited directly in the scripts; there are no command-line options. Run a fresh Python process for each comparison because the scripts keep aggregation weights in global state and execute their example comparison when imported.

## Implementation notes

The main workflow is `data_load.py` followed by `og_maxAB.py` or `og_A2B.py`. The earlier `one_graph.py` expects an edge property named `weights`, whereas the current loader writes `weight`, so it does not work directly with the current loader's output. Files ending in `_old.py` retain the previous Py2neo implementation for reference.

The repository does not include an automated reproduction of all tables in the paper; its examples and editable scripts are intended for exploring the method.
